Which JavaScript table library should you use?

We built the same table nine ways, eight libraries and a plain <table>, with 1,000 to 500,000 rows of UK house sales, and timed render, scroll and sort. Then we checked what each can do: edit, paste, select text, sort from the keyboard. We needed one for DataHub. Here is what we would use.

A table on a page

A report, an article, docs. Up to a few thousand rows.

Plain <table>

39 lines, 1 kB. 1,000 rows in about 55 ms. It prints, it copies, Ctrl-F finds every row.

Runner-up: Observable Inputs, one call and headers sort on click. Want a search box too? DataTables.

A big grid

Tens of thousands to 500,000 rows. Sort and filter out of the box. Any framework.

AG Grid Community

500,000 rows in 233 ms at 60 fps, sort and filter built in, 40 lines. The cost is 333 kB and a company that keeps clipboard and grouping for Enterprise.

Runner-up: RevoGrid, the fastest real-DOM grid here (62 ms), if you accept its corner link.

An editable grid

Spreadsheet-like. Edit cells, paste ranges.

Tabulator

Double-click to edit and paste a column both passed, with options from its own docs. Free, MIT, no framework. Give it a parent with a height.

Runner-up: RevoGrid, which passed the edit test with no config at all.

Build your own

React, your own markup and CSS.

TanStack Table + a virtualizer DataHub uses this

24 kB on a page that already ships React. You write the 150 lines, including the virtualizer. Why we chose it.
