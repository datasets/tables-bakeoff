### How to read the columns

- **totalKB** — gzipped JS + CSS the demo page downloads on first load. This is
  the honest "what does this page weigh" number.
- **libKB** — `totalKB - reactKB`. What the library costs on a page that already
  ships React. Only `tanstack` and `glide` differ from `totalKB`.
- **harnessKB** — 23.3 kB that *every* demo loads: the shared mount harness
  (`mount.js`, which pulls in hyparquet for the Parquet loader) plus
  `site.css`. It is inside `totalKB` because the page really downloads it, but
  it is not any library's doing. See the caveat below — this is the single
  biggest thing that could make a headline number misread.
- **wasmKB** — Perspective only, reported apart and **never summed into
  totalKB**. 3.98 MB raw compresses to 3.94 MB: gzip buys ~1%, which is what
  compiled Rust looks like. A single "bundle" number for Perspective beside six
  JavaScript libraries would be actively misleading, so `bundles.json` does not
  offer one.
- **lazyKB** — chunks reachable only through `import()`. Glide code-splits two
  cell-overlay editors (8.1 kB) that arrive on first edit, not on page load.
  Excluded from `totalKB`; reported so it is not simply lost.

Sanity check passes: baseline is the smallest by a wide margin, AG Grid is the
largest JS bundle, Perspective is the largest download overall once WASM counts.
No demo reports 0 kB.

## How the shared React chunk was verified

Vite's manifest expresses `imports` as **manifest keys** (`_react-Bk1giA63.js`),
not output paths (`assets/react-Bk1giA63.js`). The brief's draft normalised the
graph to be keyed by output path while leaving `imports` as keys, so the walk
looked up a key that was not in the graph, found no file on disk, and added zero
bytes — **silently**. That single namespace mismatch would have understated both
React demos by the entire 60.3 kB runtime with a green build. The walk now stays
in the key namespace and resolves to output files only at the end, and
`bytesOf()` **throws** if the manifest names a file `dist/` does not have, so
this class of bug can no longer be silent.

Verification, three ways:

1. **Unit test** — `tests/measure-bundles.test.js`, the
   `attributeChunks with a shared runtime chunk` block: a fixture with two
   entries importing one shared chunk asserts **both** get it attributed, that
   the shared chunk's own imports are followed transitively, that a diamond
   yields no duplicate (`files.length === new Set(files).size`), and that a
   cycle back to the entry terminates (Vite's manifest really contains these —
   Glide's lazy chunks list `demos/glide.html` among their imports).
2. **Printed file list** — the build prints every attributed file per demo.
   `assets/react-Bk1giA63.js` appears under both `tanstack` and `glide`, and
   under no other demo.
3. **Arithmetic against the Vite build log** — `tanstack` JS 103.1 =
   20.77 (tanstack) + 0.31 (react-host) + 60.33 (react) + 21.72 (mount); AG Grid
   326.1 = 304.36 + 21.72. Matching Vite's units and gzip level was done
   specifically so this cross-check is possible.

To make `reactKB` a lookup rather than a guess, `vite.config.js` now names the
React chunk explicitly via `manualChunks`. Rollup already hoisted React into a
shared chunk, but named it after its facade module — **`index`** — which no
filename heuristic could recognise as React (the brief's `/react/i.test(name)`
would have matched nothing and reported `reactKB: 0` for both React demos, i.e.
`libKB === totalKB`, with no error). Naming it ourselves also keeps the split
stable if a React demo is added or removed.

## Things that make a number less trustworthy than it looks

1. **The 23.3 kB harness floor is in every `totalKB`.** The plain `<table>`
   baseline uses no library at all, yet reports 24.2 kB — 23.3 of that is the
   shared mount harness (mostly hyparquet, which reads the Parquet fixture) plus
   `site.css`. Its actual own code is ~0.9 kB. Per the brief's explicit
   contract `libKB` is `totalKB − reactKB` and nothing else, so `libKB` also
   carries the floor; `harnessKB` is emitted separately precisely so the
   write-up can say "24.2 kB, of which 23.3 kB is the harness every demo pays"
   rather than implying `<table>` costs 24 kB. **Any prose that calls `libKB`
   "the library's cost" should subtract `harnessKB` or state the floor.**
2. **AG Grid's CSS is 0** because AG Grid 36 ships its theming from JavaScript.
   That is not a saving — the bytes are inside its 326 kB JS. Do not present
   AG Grid as "no stylesheet cost".
3. **`loc` is a build-cost proxy, not a quality measure, and it is crude.**
   TanStack's 166 is the largest because a headless library means you write the
   markup, the sort/filter wiring and the virtualiser yourself — that is the
   point of the number. But it counts JSX markup lines the same as logic lines,
   so React demos (which have their own component file) are structurally
   penalised against a vanilla demo that hands a config object to a constructor.
   AG Grid's 62 is real: you write a config, and get 326 kB.
4. **Perspective's WASM is only downloaded because it runs an engine, not a
   table.** Comparing 3.9 MB to a 22 kB Observable Inputs bundle is comparing
   different products. Report it, do not rank on it alone.
5. **Glide's 8.1 kB `lazyKB` is excluded from `totalKB`.** Defensible (it does
   not load on first paint) but it means Glide's "everything you eventually
   download" figure is 196.7 kB, not 188.6 kB. Only Glide is affected.
6. **Numbers move with dependency versions and with the demo set.** They are
   regenerated on every `npm run build`; `generatedAt` is in the JSON. If a
   React demo were ever removed, `manualChunks` keeps React as its own chunk, so
   `reactKB` stays comparable — that was the point of pinning it in config.
7. **The `harness` intersection is derived, not hardcoded** (the chunks common
   to all seven attributions). If a future change made all seven demos share
   some library chunk, it would be counted as harness. Worth re-reading the
   `harness.files` list if the demo set changes.
